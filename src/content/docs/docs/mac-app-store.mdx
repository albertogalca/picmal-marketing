Picmal is in two places: on [picmal.app](https://picmal.app/#pricing) and on the
Mac App Store. Same app, same price, same engines. The short version: if you live
in the Terminal, buy direct. If you would rather let Apple handle the receipt and
share the app with your family, use the App Store. Everything else is identical.

## What's the same in both

- Every conversion format, at the same quality, for images, video, audio and PDF
- Compression for images, video, audio and PDF
- All the tools: Combine Videos, Slideshow, App Icons, Remove Background, Vectorize, Merge Audio, Split by Chapter, Combine and Split PDFs, Organize Pages, Images to PDF
- Batch processing, resize modes, target file size, metadata removal
- Copyright and ownership stamping, and per-field metadata control
- Lossy and lossless PNG compression, GIF compression, SVG optimization
- Finder Services and Shortcuts
- 100% local processing. Nothing is uploaded, and it works offline

Both builds do all the work on your Mac. Neither one has an account, a server, or
a file that leaves your machine.

## What only the direct version has

Apple's sandbox is a real security boundary, not a formality, and some of what
Picmal does simply cannot happen inside it. A few other pieces use GPL-licensed
tools, which App Store licensing rules don't allow. So:

**Command line tool (`picmal-cli`).** A sandboxed app can't install a tool into
`/usr/local/bin`. If you script conversions, this is the deciding line. See
[Command line (CLI)](/docs/cli).

**Raycast extension.** It's built on the command line tool, so it goes with it.

**[Watched folders](/docs/watched-folders).** Drop a file in a folder, get a
converted one back. It depends on state the command line tool shares, so the
sandboxed build turns it off.

**Camera EXIF carried through RAW conversions.** This needs exiv2, which is GPL.
RAW conversions in the App Store build lose the camera EXIF. Everything else
about RAW decoding is the same.

**The last few percent on PNG and GIF.** Both builds compress PNG and GIF
properly. The direct build adds pngquant and gifsicle on top, which squeeze a
little more out of each file.

**Instant updates.** The direct build updates itself through Sparkle the moment I
ship. App Store updates wait for review.

**Up to 5 Macs on one license.** Picmal Pro is a direct-only plan, because App
Store licensing follows your Apple account rather than a key you can move.

## What only the App Store version has

**Apple handles everything commercial.** Purchase, updates and refunds all go
through Apple. There's no [license key](/docs/license) to keep, and nothing for
you to email me about if you lose it.

**Family Sharing.** One purchase, your household.

**The full App Sandbox.** The app asks once per folder before it saves next to
your files, and remembers. Some people want exactly that.

## Common questions

**Is the App Store version a cut-down app?** No. Every conversion and compression
feature is there, running the same engines at the same quality. What's missing is
the list above.

**Is the price different?** No. $39 either way. Picmal Pro, at $69 for 5 Macs, is
only sold direct.

**Which one gets updates first?** The direct build, usually by a day or two.

**Can I switch later?** Yes, but you'd be buying it twice. Apple and I are
separate shops, and neither can see the other's receipt. Pick based on whether
you want the command line tool, not on hedging.

**Do my files leave my Mac in either version?** Never, in either one. No uploads,
no account, no servers. That's the whole point of Picmal.
